Reading chromatograms is the first step in almost every Chromhandler workflow. Before peak assignment, integration, calibration, or quantification, the data has to be loaded in a structure that preserves which run belongs to which sample and which time point belongs to which reaction.

This chapter explains that structure from a user point of view rather than an implementation point of view.

## 🧠 The Core Mental Model

Chromhandler organizes imported data around three ideas:

- A `Handler` holds the full dataset.
- Each `sample` represents one reaction condition, one biological sample, or one experimental series.
- Each `chromatogram` is one injection or one time point within that sample.

When you read a directory, Chromhandler uses folder names and file names to build that hierarchy automatically.

## ✅ Typical Workflow

<Steps>
1. Organize your exported chromatogram data on disk so file and folder names reflect samples and reaction times.
2. Read the chromatograms with `Handler.read(...)`, which turns the exported files into `samples` and `chromatograms`.
3. Define the molecules that are present in the chromatograms and that you actually want to track, assign, quantify, or fit later.
4. Load initial-condition assignments from a CSV using `handler.load_initial_conditions(...)` so those values are attached to the existing samples in the handler.
</Steps>

This sequence is useful because each step builds on the previous one:

- data organization determines how samples and time points are inferred
- chromatogram import creates the experimental structure inside the `Handler`
- molecule definition tells Chromhandler which analytes you care about
- initial-condition tables enrich those already existing samples afterward

## 🧭 What You Usually Read First

In most workflows, the first thing that goes into a handler is not a CSV table or a list of molecule values. It is a directory of chromatogram exports.

That first read step determines:

- which samples exist
- which chromatograms belong to each sample
- which reaction times are attached to those chromatograms
- whether peak tables are already available from the vendor export

Only after that does it make sense to attach extra metadata such as initial conditions.

## ❓ Why This Matters

Chromhandler is designed for batch processing. That only works well when the software can infer a few things reliably:

- which files belong to the same sample
- which file corresponds to which reaction time
- whether a format already contains integrated peaks or only raw signal

Once those rules are understood, the rest of the workflow becomes much easier to reason about.
